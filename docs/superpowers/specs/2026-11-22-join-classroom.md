# 수업 참여코드로 수업에 들어가기 (#35)

학생이 선생님께 받은 참여코드를 입력해 수업에 들어간다. 서버 API는 `POST /api/me/classroom` (ssen-server #24).

## 동작
- 진입: 내 정보(`/account`)의 `수업 참여하기` 카드(수업이 있으면 `수업 바꾸기`) → `/join`. 교사 계정에는 이 카드가 보이지 않는다.
- `/join` 화면
  - 비로그인이면 `/login`으로 보낸다(서버에 연결할 수 없는 상태면 `/account`). 교사 계정이면 입력칸 없이 "학생 계정으로 해요"라는 안내만 보여준다.
  - 입력칸은 대문자로 바꾸고, 코드에 쓰지 않는 글자(공백 포함)는 지우고, 6자까지만 남긴다(`maxLength`는 쓰지 않는다. 공백이 낀 코드를 붙여 넣으면 브라우저가 공백까지 세어 마지막 글자를 잘라 버리기 때문이다). 코드 글자집합은 `ABCDEFGHJKMNPQRSTUVWXYZ23456789`(헷갈리는 0·1·I·L·O 제외).
  - 이미 수업이 있으면 설명에 현재 수업명과 "다른 코드를 입력하면 수업이 바뀌어요"를 덧붙인다.
- 제출 순서: 입력 검증 → `joinClassroom` → `refreshUser()`(사용자 정보의 수업명 갱신) → 서버 단어장 다시 읽기(`useBookmarks().reload()`) → 토스트 `{수업명} 수업에 참여했어요` → 홈(`/`)으로 이동. 요청 중 중복 제출은 무시한다.
- 참여하면 서버가 `GET /api/me/words`에 그 수업의 교사 단어를 합쳐서 내려주므로, 홈·학습에 교사 단어가 보인다.

## 오류 처리
| 상황 | 표시 |
| --- | --- |
| 빈 입력 | 참여 코드를 입력해 주세요 |
| 6자·글자집합 불일치 | 참여 코드를 확인해 주세요 (영문 대문자·숫자 6자) (서버 호출 없음) |
| 404 | 서버 메시지 그대로: 참여 코드를 확인해 주세요. |
| 429 | 서버 메시지 그대로: 시도 횟수를 초과했어요. 5분 뒤에 다시 시도해 주세요. (서버 메시지가 없으면 클라이언트 기본 문구) |
| 네트워크·기타 | 서버에 연결할 수 없어요 등 클라이언트 기본 문구, 그 외 요청에 실패했어요 |
| 로그인 만료 | 로그인이 만료됐어요. 다시 로그인해 주세요 |

참여 응답이 `{ id, name, code }` 형태가 아니면(null 포함) `서버 응답이 올바르지 않아요`로 거절한다.
`refreshUser`만 실패한 경우 참여는 이미 성공했으므로 오류로 보이지 않고 토스트·이동을 그대로 진행한다. 사용자 정보는 다음 실행 때 갱신된다.

## 재참여 규칙
이미 수업에 있어도 다른 코드로 다시 참여하면 수업이 바뀐다. 수업 나가기는 없다.

## 보안 메모
- 코드를 5번 틀리면 서버가 5분 동안 잠근다(429). 앱은 별도 잠금을 두지 않고 서버 응답을 그대로 보여준다.
- 코드는 서버가 공백 제거·대문자화하며, 앱도 같은 규칙으로 정규화해 보낸다.
- 교사 계정은 서버가 403으로 거절한다. 앱은 화면에서도 막는다.
